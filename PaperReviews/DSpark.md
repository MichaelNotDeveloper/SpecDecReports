# Problems of DFlash
- Text Diffusion generates tokens independently.
- Block-Size of generation is constant through entire generation.
- Anchor token steals one promising token from generation.

# Improvements of DSpark

## Anchor does not predict anchor
- Dflash : Drafter([anchor, MASK, ... MASK]) -> [anchor, token_0, ..., token_(k-1)]
- DSpark : Drafter([anchor, MASK, ... MASK]) -> [token_0, token_1, ..., token_k]

It gives simial draft quality but imporves generation speed.

## Probe for block-size estimation.
Structured text like code naturally yields high acceptance, whereas open-ended chat has significantly lower acceptance.

On the system side, the actual cost of verifying an extra token depends strictly on the engine load. Under light system load, an extra verification incurs minimal penalty even if rejected.

So we can train a probe, to minimize TV-distance between, real accaptance rates and predicted (acceptance rate means the probability of this token be accepted give all previous ones already are.)

Probe is based on hidden data from drafter and logits A[x_k] from markov-chain (or RNN history if you will).



## Semi-autoregressive generation

We wanna sample 
$p(x_k | y_{<k}) = \frac{1}{Z} p(y_{<k} | x_k) p(x_k)$
We can approximate $p(y_{<k} | x_k)$ as a function of $x_k$ using RNN or Markov head, and logits from diffusion drafter.

Here is markov head example, since it works better :
Assume markov principle Now make drained logits as a markovian matrix, column denotes logit vector, after token [k-1].
Since markov-chain will be huge (|token| x |token|), we can approximate it, with lower rank W = AB.
Choose (x_(k-1)) row of matrix A, multiply A[x] B.

> [!HINT]
> You can use logits to represent $p(x) = \exp(\text{logit}_x)$

![](https://i.ibb.co/N283984G/Screenshot-2026-10-28-at-12-41-30.png)

Traning : linear combination of losses:

1. Cross-Entopy (alpha = 0.1)
2. Total-Variation with teacher (alpha = 0.9)

> [!HINT]
> Total variation minimizes acceptance rate



## DSpark Training Data

| Dataset | Share | Notes |
|---|---:|---|
| Open-PerfectBlend | 100% | The authors used the prompts from this 1.3-million-sample instruction dataset. Responses were regenerated by each target model using its recommended sampling parameters. The dataset contains the categories below. |
| └ Chat | 17.6% | Category within Open-PerfectBlend |
| └ Math | 39.4% | Category within Open-PerfectBlend |
| └ Code | 38.9% | Category within Open-PerfectBlend |
| └ Instruction following | 4.1% | Category within Open-PerfectBlend |

The drafters were trained for 10 epochs. Data generation and evaluation used non-thinking mode.
